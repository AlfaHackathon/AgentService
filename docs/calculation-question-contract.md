# Calculation / question preflight contract

The reported synthetic attempt4 submitted `question.unit=RUB`, `targetPeriod=2027`, `frame=event_only`, `baselinePeriod=null`, `amountBasis=contract_total`, but `calculation.period=2027-01-01/2028-01-01` (also RUB). Proposal/final were equal; three prepare calls returned 200 and final save returned 400. These period representations have no declared equivalence contract.

Agent now rejects the resolved draft before accepting `submit_news_analysis` with `422 CALCULATION_QUESTION_MISMATCH` if calculation unit/period differs from question unit/targetPeriod, targetPeriod is unknown, or budget_delta baseline is unknown. The same check protects final application validation. Error feedback contains the conflicting dimensions, never the expression or source text. Existing two-submission / one-correction budget is unchanged. The host never rewrites dates or units. The model must supply an explicit source-grounded correction or preserve unknowns and omit calculation; an existing question's canonical identity/history remains immutable.

Insight prepare runs its complete prepared batch through the existing final-write normalizer before returning. Validation failures return 422 at this read-only tool boundary; final save retains its strict normalizer and 400 contract. Normalized output is deliberately discarded: this preflight neither changes the prepare response (including model conclusion) nor writes revisions/receipts. Therefore invalid full-draft shapes are rejected before tool acceptance as well as at final save. No generic HTTP 400-to-422 conversion is added to Agent.

Regression covers the exact year/date-range mismatch, resolved prior question, valid exact period/null baseline, unknown-without-calculation, explicit correction, bounded exhaustion and shared full-draft prepare/save validation. One older synthetic duplicate-question fixture also had an unrelated year/month inconsistency; its own invented terms now explicitly specify the existing calculation month so that test isolates duplicate identity. No production period normalization or evidence inference is introduced.

Agent can enforce this contract against the existing Insight runtime; the companion Insight change adds prepare/save parity for other callers. No migrations, category changes, source-scope changes, live LLM or external database are required.
